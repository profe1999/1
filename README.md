# MOEX screener pipeline

Два фоновых задания на GitHub Actions считают данные для скринера акций
MOEX, который отображается виджетом на Tilda. Виджет сам ничего не
вычисляет и не ходит во внешние API — только читает готовый `data/table.json`.

## Архитектура

```
еженедельно (понедельник)     ежедневно
smart-lab.ru  ──►  fundamentals.json  ──┐
                                          ├──►  build-daily.js ──► table.json ──► виджет на Tilda
MOEX ISS (цены/свечи/FUTOI) ─────────────┘
```

- **`data/fundamentals.json`** — медленно меняющиеся показатели (выручка,
  прибыль, активы, FCF, дивиденды, ROE, ROA) со smart-lab.ru. Обновляется раз
  в неделю — чаще нет смысла, финансовая отчётность не выходит ежедневно.
- **`data/table.json`** — то, что реально показывает виджет. Пересобирается
  ежедневно: живая цена и капитализация с MOEX ISS, MACD/RSI по свечам,
  позиции физ/юр лиц по фьючерсам (FUTOI) — и всё это объединяется с
  последними данными из `fundamentals.json`.
- **`data/manual-inputs.json`** — единственный по-настоящему ручной вход:
  оборотные активы по каждой компании (см. ниже, почему).

## Почему оборотные активы — ручной ввод

Ни MOEX ISS, ни smart-lab.ru не публикуют разбивку активов на оборотные и
внеоборотные ни в каком виде — это данные из баланса, а не из скринеров
мультипликаторов. Заполните `data/manual-inputs.json`:

```json
{ "LKOH": { "currentAssets": 1234000000000 } }
```

Без значения для конкретной компании колонки 4 (чистые активы % капитализации),
6 (прибыль/внеоборотные активы) и 9 (амортизация/внеоборотные активы) покажут
«—» именно для неё — остальные колонки при этом считаются нормально.

Внеоборотные активы считаются автоматически: `assets(smart-lab) − currentAssets(отсюда)`.

Для банков/страховых/финансовых компаний (список — `config/financial-sector.json`)
оборотные активы не используются вообще: там колонка 4 = все активы минус все
обязательства (`net_assets` со smart-lab), как и просили.

## Что ещё нет автоматического источника

- **Байбэки/казначейские акции** (колонка 10) — ни один из источников их не
  отслеживает. По умолчанию 0% (то есть предполагается, что байбэков не было).
  Если компания реально выкупала акции — впишите количество в
  `data/manual-inputs.json` (`treasurySharesCount`), и колонка начнёт
  считаться как количество × живая цена / капитализация.

## Классификация "финансовая компания"

`config/financial-sector.json` — список тикеров банков/страховых/финансовых
компаний, влияющий на формулу колонки 4 (см. выше) и на набор полей
smart-lab, которые для них запрашиваются (`net_operating_income`, `capital`,
`bank_assets` вместо `revenue`, `net_assets`, `assets`). Список ведётся
вручную — единого машиночитаемого классификатора сектора у MOEX нет; если
на бирже появится новая публичная финансовая компания, добавьте её тикер
в список.

## Установка

```bash
npm install
npm run fetch-fundamentals   # раз в неделю (см. .github/workflows/weekly.yml)
npm run build-daily          # раз в сутки (см. .github/workflows/daily.yml)
```

Оба workflow уже настроены на автоматический запуск по расписанию и на
ручной запуск (вкладка Actions → Run workflow). После первого прогона
`data/table.json` появится в репозитории — раздайте его через
`raw.githubusercontent.com/ВАШ_АККАУНТ/РЕПО/main/data/table.json` (или
включите GitHub Pages) и укажите этот URL в виджете на Tilda (`DATA_URL`
в начале `<script>`).

## Если тикер не находится на smart-lab

`data/review-queue-weekly.json` покажет `smartlab_no_data` — обычно это
значит, что smart-lab использует другой тикер в URL, чем MOEX SECID.
Впишите соответствие в `config/smartlab-ticker-overrides.json`.

## Ограничение источника данных

Внизу страниц smart-lab.ru указано, что источник и правообладатель
биржевой информации — ПАО Московская биржа, и её дальнейшее распространение
ограничено без письменного согласия биржи. Это фактическая формулировка с
сайта-источника, не наша юридическая оценка (мы не даём юридических
консультаций) — стоит учитывать при публичном использовании собранных
данных на своём сайте.
